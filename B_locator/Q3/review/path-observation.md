## 从图上能直接看出来的四件事

1. **"向外绕一圈"是主路径形态，不是"沿着示向度逼近"。**
   A/B/C/D 四张图里机器狗都走成近似多边形环路，先扫外圈再回到内侧；
   示向度射线（紫色）只用于选中下一个停点，**没有出现沿某条射线一路前推的退化几何**。
   这正是问题 1/问题 2 的结论在起作用：沿示向度逼近会让交会区域无界。

2. **gap=450 → 1000 的效果在路径上非常直观。**
   对比 A 与 B（同一案例、只改这一个参数）：B 的橙色停点明显更密（324 次检测 vs 188 次），
   虚拟时间多 1000 s，而清除结果完全相同（10/10）。
   即旧参数把时间花在"在已测过的位置附近重复听同一个频道"上。

3. **E vs F 是两个极端，说明指标由"发现"而非"清除"决定。**
   * E（源挤在圆心）：**平均定位清除时间 57.7 s** —— 因为几乎不用找；
   * F（1 个源在正东 1700 m，有效接收半径 1000 m）：**2795.7 s** —— 机器人把
     西侧与南侧几乎扫遍（258 次检测、15 438 m 行程）才在 (1100,-1400) 附近第一次听到它。
   两者清除率都是 1.000。⇒ 平均定位清除时间这个指标的分子几乎全是"搜索"。

4. **F 同时暴露了那个"空地乱蹭"缺陷。**
   F 的路径能清楚看到下半圆的一串锯齿（相邻停点只相距几百米）。
   机器人**没有把"整个南侧都测不到"当作覆盖信息**，所以会在已被证明为空的方向上
   反复小步挪动；这正是 `review/P3-design.md` §5.4 说的"无信息阶段"问题 ——
   改进办法是按 1000 m 六边形格点做一次显式扫掠，扫完即可确定性收工。

## 复现

```powershell
python src/p3_paths.py                    # 六组场景 + 总览图
python src/p3_paths.py --anim             # 额外生成逐帧动画 GIF（默认第一组）
python src/p3_paths.py --live             # 额外把两局在线 protocol.jsonl 重画成路径
```

想换场景（例如"源全在某个方向""12 个源都在 r>1500"），改 `src/p3_paths.py` 里的
`scenarios()` 即可；想换参数直接给 `P3Config(...)`，例如
`scenario("G_宽间隔", seed=20260913, nosignal_gap_m=1500.0)`。
